# Paseo 三端本地打包流程

> 目标：在 Ubuntu 构建服务端、Android ARM64 APK 和 Windows x64 zip，并启动临时下载服务。
> 版本以根 `package.json` 为准。完整打包只使用下述两个版本化入口，不再由代理复制各阶段命令。

## 0. 固定环境与 worktree

- 产品构建目录：`/home/yangfei/Projects/paseo`，正常停留在 `rw-main`，长期保留 Android/Gradle/Metro/NDK/Electron 缓存。
- 控制面：独立的 `chore/build-paseo` worktree，只保存 `dwyanewang/` 下的清单、脚本和文档，不合并进产品分支。
- `rw-main` 只由上游镜像 `main` 和 [`rw-main-branches.txt`](rw-main-branches.txt) 中的功能分支按顺序重建。不要向旧 `rw-main` 追加 merge。
- worktree 共享 Git refs，但源码、`node_modules`、`dist` 和构建缓存独立。任何相关 worktree 有改动或 detached HEAD 时停止，不 stash、不覆盖。
- 工具版本来自 `.tool-versions` / `.mise.toml`；脚本会在自己的 shell 中安装并激活 mise。Wine 只使用 `~/.local/share/paseo/wineprefix`，绝不删除默认 `~/.wine`。
- 禁止重启或触碰 6767 主 daemon。

先定位控制面：

```bash
paseo_build_root=/home/yangfei/Projects/paseo
paseo_chore_root=$(git worktree list --porcelain | awk '
  /^worktree / { path = substr($0, 10) }
  $0 == "branch refs/heads/chore/build-paseo" { print path }
')
[[ -n "$paseo_chore_root" ]]
```

## 1. 完整同步与 readiness gate

除非用户明确要求“不拉取/不同步”，每次从控制面单次调用：

```bash
paseo_preflight_state="$paseo_build_root/.dev/build-paseo-preflight.env"
bash "$paseo_chore_root/dwyanewang/prepare-rw-main-for-build.sh" \
  --build-root "$paseo_build_root" \
  --state-file "$paseo_preflight_state" \
  --push
```

用户明确要求新增项时，在同一命令末尾按用户给出的顺序追加：

```bash
--add-pr 2345
--add-branch feat/example
```

新 PR 不自动发现。`--add-pr` 只接受 `dwyanewang` 拥有的上游 PR 并自动解析源分支；`--add-branch` 用于没有 PR 的长期个人分支。“新增项”和“不拉取/不同步”不能同时执行。

前置脚本统一完成：

1. 检查控制面、构建目录、`main` 及清单功能分支 worktree 的洁净度。
2. fetch upstream/origin，将本地 `main` 安全快进到 `upstream/main`，并推送 fork。
3. 批量查询清单 PR，自动删除已经合入且被本地 `main` 包含的项。
4. 按每项的 `reviewed-main` / `reviewed-head` 判断是否需要语义审查。
5. 原子重建候选 `rw-main`，刷新跨 workspace 声明，运行 format/typecheck/lint，通过后才移动并按需推送 `rw-main`。
6. 成功时原子写 ready state；失败或暂停前删除旧 state，防止复用过期结果。

### 1.1 退出码与语义审查

- `0`：readiness gate 已通过，可以进入第 2 节。`No-op:` 表示 main、清单和全部分支 head 未变化，可安全复用现有 merge 链。
- `3`：不是脚本故障，必须审查报告列出的每个区间。阅读全部提交主题、路径；疑似相同能力时继续看 PR 说明和完整 diff。patch 等价或路径重叠只是线索，不是语义结论。
- `4`：清单已原子更新，但尚未重建。运行 `npm run format`，确认仅有预期清单改动，提交 `chore(build): sync rw-main branches` 并推送 `origin/chore/build-paseo`，再不带增删参数重跑。
- 其他非零：立即停止并按日志诊断。没有 ready state 时禁止启动服务端、Android 或 Windows。

语义审查只有四种结论：

1. 上游未吸收：保留该分支。
2. 上游已完整吸收：重跑时传 `--remove-branch <分支>`。
3. 上游只吸收一部分：到源功能分支自己的 worktree rebase 最新 `main`、删除重复实现、运行定向验证并 `git push --force-with-lease`，再重新审查。
4. 无法确定：询问用户；不得擅自确认或继续重建。

确认所有保留项后，用同一个前置命令追加：

```bash
--accept-main-review "$(git -C "$paseo_build_root" rev-parse main)"
```

若同时删除条目，再追加对应 `--remove-branch`。清单坐标变化同样属于清单改动，按退出码 `4` 的要求提交。提交正文记录审查区间和删改依据。

### 1.2 readiness 失败处理

- 同一 workspace 的 `src`/测试 import 报成员不存在、helper 改名或参数不符，通常是分支组合不兼容。按报错文件和 Git 归属修复源功能分支，不要在候选或 `rw-main` 直接改源码。
- 只有报错实际跨 workspace 指向生成的 `dist/*.d.ts` 时才先重建声明拥有方：protocol/client 用 `npm run build:client`，server/CLI/relay 链用 `npm run build:server`。
- 源分支修复后运行 `npm run format`、`npm run typecheck`、`npm run lint` 和相关单个测试。app Playwright 定向测试必须显式清空外部密码：`PASEO_PASSWORD= npm run test:e2e --workspace=@getpaseo/app -- <spec>`。
- 完整排查按错误文本查询 [踩坑记录.md](踩坑记录.md)，不要每轮预读全文。

## 2. 正式三端产物链

readiness 成功后，把 state 原样交给版本化脚本。整个命令作为一个长后台任务运行，等进程输出或结束通知，不现场生成 heredoc，不主动定时轮询：

```bash
bash "$paseo_chore_root/dwyanewang/build-paseo-artifacts.sh" \
  --build-root "$paseo_build_root" \
  --preflight-state "$paseo_preflight_state"
```

用户明确要求“不拉取/不同步”时跳过第 1 节，改用：

```bash
bash "$paseo_chore_root/dwyanewang/build-paseo-artifacts.sh" \
  --build-root "$paseo_build_root" \
  --skip-preflight
```

`--skip-preflight` 仍要求控制面和当前产品 checkout 洁净，并保守运行完整 `build:server`。正常完整同步绝不使用它。可选参数：`--download-port <端口>`、`--download-ttl <秒>`、`--no-serve-dist`；默认端口 8800、存活 10800 秒，明确拒绝 6767。

脚本负责且必须保持以下语义：

- 在删除旧产物前验证 ready state、`rw-main` HEAD、两个 worktree 洁净度；跳过同步模式验证当前 checkout。
- 精确删除本版本旧 APK/zip并写本轮标记；重生成 terminal-webview，成功或失败均用 EXIT trap 只还原该文件。
- 服务端根据 state 选择完整构建或复用刚重建的声明，并验证 server、CLI、protocol 真实入口。
- Android 每次 prebuild 后应用 8 个 Metro worker 与 `local-balanced` Hermes；先单 worker 跑 Metro/Hermes，再以 8 个 Gradle worker 打 ARM64 原生包。两段均使用 cgroup 资源画像；第二段必须让 bundle producer 留在 task graph 并命中 `UP-TO-DATE`。
- Windows 构建 Electron web、主进程和 x64 zip；使用 `PASEO_WEB_PLATFORM=electron`、Wine 专用 prefix 与压缩级别 3，不生成 nsis。
- 校验新产物、还原 terminal-webview、确认两个 worktree 洁净，再启动下载服务。任何失败保留真实退出码且不生成成功结果文件。

## 3. 结果与校验

每轮目录为 `$paseo_build_root/.dev/build-paseo-runs/<时间>-<PID>/`：

| 文件          | 含义                                                               |
| ------------- | ------------------------------------------------------------------ |
| `build.log`   | 完整产物链输出                                                     |
| `stages.log`  | 带时间戳的阶段切换                                                 |
| `exit-status` | 真实退出码，成功或失败均写                                         |
| `result.env`  | 仅成功时原子生成；包含版本、产物、资源目录、服务端模式和产物链墙钟 |

固定产物：

| 端      | 路径                                                                                 |
| ------- | ------------------------------------------------------------------------------------ |
| 服务端  | `packages/server/dist/server/server/exports.js`，CLI 为 `packages/cli/dist/index.js` |
| Android | `packages/app/android/app/build/outputs/apk/release/app-release.apk`                 |
| Windows | `packages/desktop/release/Paseo-Setup-<版本>-x64.zip`                                |

Android 画像目录由 `result.env` 的 `paseo_artifact_android_profile_dir` 给出。两份 summary 必须是 `exit_status=0`，汇报 `command_wall_seconds`、`average_cpu_cores`、`peak_sampled_cpu_cores`、`host_cpu_percent`、`memory_peak_bytes`、`swap_peak_bytes`；不要用含采样收尾的 `service_runtime` 代替阶段墙钟。

## 4. 下载服务与交付

产物脚本默认已经启动下载服务并打印实际 LAN/Tailscale 地址；不要写死 VM IP。Tailscale 未登录只会少一个地址，不是构建失败。需要刷新或提前停止时从控制面运行：

```bash
bash "$paseo_chore_root/dwyanewang/serve-dist.sh" keep
bash "$paseo_chore_root/dwyanewang/serve-dist.sh" stop
```

`keep` 只刷新产物且不重置原 TTL；`stop` 只停止状态文件中身份匹配的自有服务。未知端口占用时报告，不杀其他进程。

最终汇报：清单增删及提交（若有）、三端产物路径/体积/mtime、Android 两段资源数据、下载地址和真实总墙钟。总墙钟从用户发起打包开始，到产物复核与下载服务就绪结束；`paseo_artifact_total_seconds` 只代表正式产物链，不能扣除阅读、审查、冲突修复或失败重试。
