# Paseo 本地打包流程（服务端 / 安卓 / Windows x64 桌面端）

> 适用环境：Ubuntu 24.04 · Node 22 / Java 17 / Android SDK 均由 mise 管理
> 本仓库为 npm workspace 单仓多包（monorepo），版本 0.1.85
> 顺序：**拉代码 → 服务端 → 安卓 → Windows**，每步成功再进行下一步

---

## 0. 环境变量（mise 未在 shell 激活时，每个构建 shell 都要先 export）

```bash
export ANDROID_HOME=/home/yangfei/.local/share/mise/installs/android-sdk/1.0
export ANDROID_SDK_ROOT=$ANDROID_HOME
export JAVA_HOME=/home/yangfei/.local/share/mise/installs/java/17.0.2
export PATH=$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$PATH
```

> 若已在 `.bashrc` 里 `eval "$(mise activate bash)"`，可跳过本节。

## 1. 拉取最新代码

```bash
cd ~/Projects/paseo
git pull --ff-only          # 快进式拉取最新 main
npm install                 # 同步依赖（拉取可能新增/变更依赖）
```

**校验**

```bash
git log -1 --oneline                       # 确认 HEAD 已是最新
git rev-parse HEAD; git rev-parse origin/main   # 两者一致即同步成功
```

> 若 `npm install` 报 `ENOTEMPTY` 或之后 `tsc: not found`：
>
> ```bash
> rm -rf node_modules/**/.vitest-*
> npm rebuild
> ```

## 2. 打包服务端

```bash
cd ~/Projects/paseo
npm run build:server
```

该脚本依次构建：highlight → relay → protocol → client → server → cli。

**校验**（注意 server/protocol 用 `exports` 而非 `index.js`）

```bash
test -f packages/cli/dist/index.js && echo CLI_OK
ls packages/server/dist/server/server/exports.js     # server 真实入口
ls packages/protocol/dist/*.js | head                # protocol 逐文件导出
```

退出码 0 且上述文件存在即成功。

## 3. 打包安卓端 APK

```bash
cd ~/Projects/paseo/packages/app
# 3.1 生成/更新原生工程（CI=1 避免 --non-interactive 弃用告警）
CI=1 npx cross-env APP_VARIANT=production expo prebuild --platform android --non-interactive

# 3.2 gradle 打 release APK（限制资源，防爆内存）
cd android
./gradlew assembleRelease --no-daemon --max-workers=4 -Dorg.gradle.jvmargs="-Xmx4g"
```

**产物**

```
~/Projects/paseo/packages/app/android/app/build/outputs/apk/release/app-release.apk   (~168 MB)
```

**校验**

```bash
ls -lh ~/Projects/paseo/packages/app/android/app/build/outputs/apk/release/app-release.apk
# 构建日志应有 BUILD SUCCESSFUL
```

**说明**

- 首次约 17 分钟（含 NDK 原生编译），二次走缓存约 5 分钟。
- **不要清理** gradle 缓存 / `.cxx` / 各模块 `build/`，否则下次重编原生库。
- release 包用 debug keystore 签名，自测够用，不能上架商店。
- 装到手机：`adb install -r <apk路径>`（手机开 USB 调试），或手动拷贝安装（允许未知来源）。

## 4. 打包 Windows x64 桌面端（Electron）

> 在 Linux 上打 Windows 包依赖 **wine**（electron-builder 用它跑 rcedit 写图标/版本号）。
> 首次需安装并初始化 wine，见步骤 4.0。

### 4.0 wine 准备（仅首次 / 出问题时）

```bash
# 安装 32 位 wine（rcedit-ia32.exe 是 32 位程序）
sudo dpkg --add-architecture i386
sudo apt-get update
sudo apt-get install -y wine32:i386
sudo dpkg --configure -a          # 确保包状态是 ii 而非 iU

# 重建 wine prefix 以生成 32 位子系统（syswow64）
rm -rf ~/.wine
WINEARCH=win64 wineboot --init

# 验证
ls -la ~/.wine/drive_c/windows/syswow64/ntdll.dll    # 应存在
wine ~/.cache/electron-builder/winCodeSign/winCodeSign-2.6.0/rcedit-ia32.exe --help   # 应打印帮助
```

### 4.1 完整构建（从零）

```bash
cd ~/Projects/paseo
export PYTHONPATH= PYTHONHOME= WINEDEBUG=-all CI=1
npm run build:app-deps                                          # highlight + client + two-way-audio
( cd packages/app && cross-env PASEO_WEB_PLATFORM=electron npx expo export --platform web )   # 导出 electron 用 web bundle
npm run build:main --workspace=@getpaseo/desktop               # tsc 编主进程
cd packages/desktop
npx electron-builder --config electron-builder.yml --win zip --x64 --publish never
```

> **只打 zip（用户偏好）**：用 `--win zip`，不打 nsis 安装包（exe）。zip 解压即用，无需重复生成安装程序。
> 如确实需要安装包，再加回 `nsis`：`--win nsis zip`。

### 4.2 仅续打（前面步骤已成功、只想重跑 electron-builder 时）

```bash
cd ~/Projects/paseo/packages/desktop
export PYTHONPATH= PYTHONHOME= WINEDEBUG=-all CI=1
npx electron-builder --config electron-builder.yml --win zip --x64 --publish never
```

**产物**

```
~/Projects/paseo/packages/desktop/release/Paseo-Setup-0.1.85-x64.zip   (免安装版, ~151 MB)
```

**校验**

```bash
ls -lh ~/Projects/paseo/packages/desktop/release/*.zip
# 构建日志末尾应有 electron-builder 退出码 0
```

> 兜底：若不想折腾 wine，删除 `electron-builder.yml` 里的 `win.icon` 即可跳过 rcedit、无需 wine（代价：默认图标、缺版本元数据）。

## 5. 传输到物理机（172.16.21.200，Win11）

**网络拓扑**：本机是 VM（网卡 IP `172.18.6.118`），物理机是 `172.16.21.200`。
经测试：**VM 出站受限 → ping 不通物理机；但物理机能访问 VM 的 `172.18.6.118`**。
因此传输方向只能是 **物理机主动来拉**：VM 起 HTTP 服务，物理机用浏览器下载。

> ⚠️ 不要尝试从 VM 用 scp/smb 主动推送到物理机——VM 出站不通，会失败。

### 5.1 一键起服务（推荐，存活 3 小时自动清理）

**打包成功后**运行同目录脚本 [`serve-dist.sh`](serve-dist.sh)，它会汇集 APK+zip、起 HTTP 服务、并用 `timeout` 控制 **3 小时后自动停服并删除 staging 目录**：

```bash
bash ~/Projects/paseo/dwyanewang/serve-dist.sh            # 端口 8800，刷新文件并(重新)计时 3 小时
bash ~/Projects/paseo/dwyanewang/serve-dist.sh 8800 10800 # 自定义 端口 存活秒数
bash ~/Projects/paseo/dwyanewang/serve-dist.sh keep       # 沿用在跑的服务、只刷新文件，不重置计时
bash ~/Projects/paseo/dwyanewang/serve-dist.sh stop       # 提前手动停服 + 清理
```

脚本输出会打印物理机访问地址（自动探测 VM IP）。要点：

- **幂等自愈**：3 小时内再次打包后重跑脚本，默认会停掉旧服务、用最新产物重起、**计时重置为 3 小时**（不会端口冲突）。想保留原计时只刷新文件用 `keep`。
- 用 `setsid` 脱离会话，**跨 session 存活**（关掉 Claude 会话也不影响）。
- 3 小时由 `timeout 10800` 控制，到点自动 `kill` 并 `rm -rf /tmp/paseo-dist`，无需手动收尾。
- 版本号从 zip 文件名自动提取，产物命名 `paseo-android-<版本>.apk` / `paseo-desktop-win-x64-<版本>.zip`。
- **多个 zip 时按修改时间取最新**（不是字母序，避免 `release/` 残留旧版本被选错），并**只保留最近 2 个 zip**，更旧的连同 blockmap 自动删除。

### 5.2 在物理机（Win11）上下载

浏览器打开（实测此地址可达，端口默认 8800）：

```
http://172.18.6.118:8800/
```

点击下载两个文件即可。

> 若打不开：在物理机 PowerShell 跑 `Test-NetConnection 172.18.6.118 -Port 8800` 看是否通；
> VM 的 IP 可能随环境变化，以脚本输出的地址为准（脚本会自动探测并打印）。

### 5.3 提前停服（可选，否则 6h 自动清理）

```bash
bash ~/Projects/paseo/dwyanewang/serve-dist.sh stop
```

> 注意：本环境用 `pkill -f http.server` 偶发异常退出码（误杀关联进程），脚本内部已改用"按端口取 PID 再 kill"。
